### en-GB (added 2026-10-25, for review in English)

17 lesson sets that mirror part of the de-DE pilot: Reception Maths,
Numbers to 10 (6 sets); Reception English, Hearing sounds (4); Year 2
Maths, Numbers to 100 (5); French learning year 1, Listening (2). The
fact screens say "Did you know?" in place of "Wusstest du?".

## What changes

1. **A question to open Learn.** The first Learn screen asks something
   the child can guess before being told ("Was glaubst du: sind hier mehr
   rote oder mehr blaue Plättchen?"). Spoken, then answered on the next
   screen. It counts for nothing.
2. **One "Wusstest du?" per lesson set.** A Learn screen in one lesson,
   a true and checked fact the child will want to repeat, linked to the
   skill. No invented facts.
3. **No more than three tasks of one type in a row**, by reordering or by
   swapping a task for an equivalent one of another type. Drills where
   speed on one task type is the point (Blitzlesen, facts to know by heart)
   may keep longer runs.
4. **Pictures and situations where they help.** Mathe tasks get
   `show: { object, count }` or a small situation (a bakery, a bus, a
   football match) where a bare number is dull, using only pictures that
   exist in assets/objects.yaml. Practise may move from `plain` to
   `in-context`.
5. **Humour in wrong options where the right answer stays clear.**

## What does not change

No structural change: no schema, no new fields or task types, no new or
renamed ids, same lessons per set, same skills, prerequisites, parts and
check pools (a task swapped for another type keeps its `id` and `part`).
Every set still meets the authoring checks in docs/lesson-anatomy.md and
builds with no warnings. New spoken lines are narrated with
assets/tools/narration.py.

## Then

Parents compare old and new lessons (the decisions doc, question 14).
Decide on the full pass after that; if it goes ahead, add checks for
rules 1 to 3 to lessons-check.mjs.

## Full pass (started 2026-10-25)

Decided after the pilot: every finished lesson set in de-DE and en-GB gets
the same pass, 863 sets in 84 batches of about 10, run as waves of 8
agents. After each wave: build, structure check against the last commit,
narration, commit.

### Brief for each agent

1. Read this file, docs/plans/de-DE/fun.md, docs/lesson-anatomy.md
   ("Activities", "Authoring checks", "Check pools"), docs/task-types.md,
   assets/drawn.yaml, and AGENTS.md (lessons are written by hand; no
   scripts that write task text).
2. Apply rules 1 to 5 above to every set in the batch. German sets say
   "Wusstest du?", English and French sets (en-GB) "Did you know?". In
   lessons without reading (Reception, Stufe 0), the fact screen's text is
   only "Wusstest du?" or "Did you know?" and the fact is in `say`.
3. Lessons from the pilot:
   - Never drop a Learn screen that teaches something Practise asks.
     Rewrite the first screen as the question, or add one screen.
   - Text, say, audio and the picture on a screen must match (a screen
     that says "Clap!" shows clap and plays the clap phrase).
   - A fact must be certain and must not contradict what the lesson
     teaches (house numbers that are not neighbours, in a lesson on
     neighbours, was swapped out). Prefer facts not already used:
     `grep -rh "Wusstest du\|Did you know" twist/lessons`.
   - Funny options must keep the answer unambiguous; use funny feedback
     where an extra option would blur it.
4. Nothing structural changes: ids, parts, check pools, lesson counts,
   builds_on, stage sizes. A task that changes type keeps its id and part.
5. `node twist/build.mjs` reports no error or warning in the batch's
   files. Other agents edit other files at the same time.
6. No commits, no narration. Report in under 150 words: facts used,
   anything unsure, build result.
