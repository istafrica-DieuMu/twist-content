Twist Screen Sources

Where every text, picture and sound on a Twist lesson screen comes from: the label the lesson player gives it, the field in the v2 lesson payload that carries it, and the key in the twist-content records or the file in twist/assets/ behind it. A companion to the Twist Mobile API v2 page.

How to read this

The labels are the R&D lesson player's own names for the parts of each screen. Turn on Settings › Label the parts in twist/pages/player/index.html to see them on the live screen; Screen anatomy lists them too. Each row below adds what that list leaves out: the v2 field and the exact source.

in v2 the field exists in the v2 typesadd to v2 the screen needs it and v2 does not carry it yetapp works it out computed on the device from other fields

Paths in the source column are relative to twist/ in istafrica-DieuMu/twist-content. A lesson's record is lessons/<curriculum>/<year>/<subject>/<skill-slug>.yaml; "set" means that file, "lesson" one entry of its lessons[].

From the repo to the screen

1. Records and assetsLessons, skills, phrases, voices and every picture and clip live in twist-content: lessons/, competencies/, assets/.
2. ConverterReads the records, resolves every picture, pose and clip to an asset path, and writes the importer's JSON. Who builds it is the open decision on the handoff page; the v2 mock already does this conversion.
3. Asset uploadEach file in twist/assets/ is uploaded once per content version, keeping its path.
4. BackendStores the lesson JSON and returns absolute URLs in GET /v2/lessons/{lessonId}.
5. AppCaches the JSON per contentVersion and the media its media cache finds in it; draws the drawn components itself.

Finding a narration clip

A clip's file name is a hash of the words it speaks, so the converter finds it from the text alone and identical lines share one clip.

line-id = sha1( lang + "|" + spoken(text) ).hex[0..10]
file    = narration/<voice>/<line-id>.mp3
  • lang is the set's language (de or en); a target-language line (English in an Englisch lesson, French) uses target_language.
  • spoken() rewrites what is written for the screen into what is said: + plus, − minus, = gleich / equals, _ wie viel / what, numbers into words in German, 5,70 € into "fünf Euro siebzig", × and fractions into words in English. Two copies must stay identical: assets/tools/narration.py spoken() and pages/player/build.mjs spoken(). The converter must use the same rule, or import one of them.
  • Which text: a task's say if it has one, else its text. Options, hints, feedback, Learn screens, lesson titles and phrases are each their own line.
  • Index: assets/narration/lines.yaml lists every line (id, language, text, where it is used, its voices); assets/narration/<voice>.yaml logs each made clip and its listening check.

Drawing rules the app must copy

  • A number line hides its answer. On a Rechenstrich, when the task's answer is the last landing point, that label reads "?" (31 tasks). Learn screens show the whole line.
  • Frames break at " | ". In a fill-in frame the separator starts a new line; no bar is drawn.
  • Ordering tasks draw their show above the cards (150 tasks have a picture or chart).
  • Scattered groups of more than 12 use a wider grid.
  • A screen gives way in turn when it does not fit: the picture, then the question text, then the answer area, so controls are never cut off. Tile text shrinks so a sum never breaks over two lines.
  • A drawn Bauplan names its rows hinten and vorne (back and front).
  • A pictogram takes per for what one picture stands for; key is an option's id.

Drawings

The 37 drawn components are drawn by the app from a task's show data; no image file stands behind them, except the object pictures some of them hold. Each card shows one real use from the lessons, drawn by the R&D lesson player, with the record that produced it. The data fields are documented in twist/assets/drawn.yaml; the player's drawing code (twist/pages/player/template.html, function drawn) is the reference to copy. The lessons use them 14,894 times.

In v2 the component travels as show.drawn with the same data fields, and pictures inside it as show.imageUrls. Where a task type makes a drawing touchable (a number line in point_on_line, a clock in clock_hands_drag, a grid in point_on_grid, a ten-frame in drag_and_drop_count), the card says so.

Changes for the v2 page

The v2 page was agreed on 16 Oct 2026 at content version eb9c2e7f. The content has moved since; these are the points where the screens and the contract now differ.

  1. Check pools. A CHECK activity can hold 20 tasks with draw: 5 and a part on each (6 with draw: 3 for a quick check). The backend draws one attempt with drawCheck (twist/pages/player/practice-rules.mjs) and sends only those tasks; it stores the last attempt so the next one differs. 225 of 918 sets have pools so far.
  2. Skill states. SECURE is now can_do, MASTERED is remembered, NEEDS_RECAP is needs_refresh, and recaps follow the age band (1, 4, 10 days at ages 4 to 5; 2, 7, 14 at 6 to 7; 2, 7, 21 at 8 to 10). See docs/lesson-anatomy.md, Mastery.
  3. Subject colours in config.colours, keyed by subject, for the start screen, the activity screens and the progress bar.
  4. Pose rotation: state the player's rule (above) so the app and the player show the same pose.
  5. Practice: drill banks (twist/drills/) and practice sessions as in docs/practice.md.
  6. The drawing rules listed under Task screen.

What today's app does with these fields

From ist-schoolido (read on 19 Oct 2026). These are the places where the current app would lose something a Twist screen needs.

  • The goal is never shown. The module's learning objective is read into module_metadata.description and no screen uses it; Twist shows canDo on every lesson start.
  • Hint audio never plays and feedback audio is dropped in the adapter; every Twist hint and feedback line has a clip.
  • UI text is hard-coded English ("ANSWER", "CONTINUE", "TRY AGAIN", "HINT n OF m") with no localisation; Twist lessons run in German or English by the lesson's language.
  • Mascots are bundled in the app (assets/images/states/); Twist has 21 screen poses and 24 topic poses.
  • Media URLs already arrive absolute and are cached by a regex over the JSON (services/quiz/mediaCache.ts), which works unchanged for Twist.
