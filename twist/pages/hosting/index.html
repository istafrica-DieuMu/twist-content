Twist Player Hosting

How to run the Twist lesson player on our server: the lessons, Practice, Drawings and Task types, for people signed in with their own account, with every picture and narration clip, and feedback pinned to app screens. It is a Node script and a folder of files; there is no database and no build step. Accounts and feedback are two JSON files on the server until the IST-B2C backend holds them.

NeedsLinux, Node 22 or newer, git
Disk8 GB free (the clone is about 3.4 GB)
Memory512 MB is enough
Ports443 and 80 open; the app itself on 127.0.0.1:8080 only

Set it up

  1. Get read access to the repo

    The repo istafrica-DieuMu/twist-content on GitHub is private. Create an SSH key on the server and ask the repo owner to add it as a read-only deploy key.

    sudo useradd --system --create-home --home-dir /opt/twist twist
sudo -u twist mkdir -p -m 700 /opt/twist/.ssh
sudo -u twist ssh-keygen -t ed25519 -N "" -f /opt/twist/.ssh/id_ed25519
sudo cat /opt/twist/.ssh/id_ed25519.pub     # send this to the repo owner

  2. Clone it

    --depth 1 leaves out the history, which would add another 3.8 GB. The narration clips are most of the size, so the first clone takes a while. The first connection asks to confirm GitHub's host key: answer yes.

    sudo -u twist git clone --depth 1 git@github.com:istafrica-DieuMu/twist-content.git /opt/twist/twist-content
node --version     # must say v22 or newer

  3. Choose the first admin

    Everyone signs in with their own account. TWIST_USER and TWIST_PASS make the first admin, once, while there are no accounts; that admin adds everyone else on the player's Users tab and can hand out the manager role, so managers add their own testers. Keep the password in the password manager, never in chat or email. The file stays outside the repo and readable only by root. Accounts and feedback are kept in TWIST_DATA; back that folder up. With TWIST_API_URL set they live on the IST-B2C backend instead (twist/docs/feedback-backend.md).

    sudo tee /etc/twist-player.env >/dev/null <<'EOF'
TWIST_USER=you@ist.com
TWIST_PASS=change-me-to-a-long-random-password
TWIST_DATA=/opt/twist/data
COOKIE_SECURE=1
PORT=8080
EOF
sudo -u twist mkdir -p /opt/twist/data
sudo chmod 600 /etc/twist-player.env

  4. Run it as a service

    The app listens on 127.0.0.1 only, so nobody reaches it without going through HTTPS.

    sudo tee /etc/systemd/system/twist-player.service >/dev/null <<'EOF'
[Unit]
Description=Twist lesson player
After=network.target

[Service]
User=twist
WorkingDirectory=/opt/twist/twist-content
EnvironmentFile=/etc/twist-player.env
ExecStart=/usr/bin/node twist/serve.mjs
Restart=on-failure
NoNewPrivileges=true
ProtectSystem=full
ProtectHome=true

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now twist-player
sudo systemctl status twist-player      # "Twist player on http://127.0.0.1:8080/"

    If node is not in /usr/bin, put the path from which node in ExecStart.

  5. Put HTTPS in front

    The sign-in form and the session cookie must never travel in clear text, so the site must only be reachable over HTTPS. With Caddy, which gets the certificate by itself (replace the domain with ours, pointed at this server):

    # /etc/caddy/Caddyfile
twist.example.org {
    reverse_proxy 127.0.0.1:8080
}

    Or with nginx and a certificate from certbot:

    server {
    listen 443 ssl;
    server_name twist.example.org;
    ssl_certificate     /etc/letsencrypt/live/twist.example.org/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/twist.example.org/privkey.pem;
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
    }
}
server { listen 80; server_name twist.example.org; return 301 https://$host$request_uri; }

  6. Check it

    curl -s -o /dev/null -w "%{http_code}\n" https://twist.example.org/healthz                # 200
curl -s -o /dev/null -w "%{http_code}\n" https://twist.example.org/pages/player/          # 302: to the sign-in page
# from another machine: the app port must not answer
curl -s -o /dev/null -w "%{http_code}\n" --connect-timeout 3 http://SERVER-IP:8080/          # 000 (no connection)

    Then open the site in a browser, sign in as the first admin, choose a lesson and press the speaker: the voice should play. On an iPhone, check one lesson with sound too. On the Users tab, add the people who will test.

Update it

The R&D team pushes new lessons and audio to main. The built player is in the repo, so updating is a pull and a restart; run it when they ask, or nightly from cron. A restart signs everyone out (sessions are kept in memory); accounts and feedback stay.

cd /opt/twist/twist-content
sudo -u twist git fetch --depth 1 origin main
sudo -u twist git reset --hard origin/main
sudo systemctl restart twist-player

The reset throws away any change made on the server, which is intended: nothing should be edited there.

What is served

Only twist/pages/ (the player, Drawings, Task types and the other pages) and twist/assets/ (pictures, mascot, narration). The lesson files and the rest of the repo answer 404. Audio supports range requests; HTML and JS are compressed by the app (the player page is 25 MB, 4.6 MB over the wire), so leave compression in the proxy off or on, either works.

If something goes wrong

What you seeWhat to do
The service stops at oncejournalctl -u twist-player. A permission error on accounts.json means TWIST_DATA is not writable by the twist user.
Nobody can sign in, there is no account yetTWIST_USER and TWIST_PASS were not in the env file the first time it started. Add them and restart: the first admin is made while there are no accounts.
Signing in goes back to the sign-in pageThe session cookie is Secure and the site is opened over plain HTTP. Use HTTPS, or leave out COOKIE_SECURE on a laptop.
Someone forgot their passwordTheir manager, or an admin, sets a new one on the Users tab.
502 from the proxyThe service is not running, or listens on another port than the proxy uses: compare PORT with the proxy line.
No sound, or no sound on iPhone onlyThe proxy must pass Range requests through (Caddy and nginx do by default). Check one clip: in the browser's network panel, a clip's request answers 206.
The page takes long the first timeNormal: 4.6 MB for the player, then pictures and clips as lessons are opened. After that the browser caches them.
git fetch is refusedThe deploy key was removed or the repo moved; ask the repo owner.
Disk filling upEach update replaces files in place; the shallow clone stays near 3.5 GB. git gc --prune=now clears old objects.

Keep these four: HTTPS only, the first admin's password kept in the password manager, port 8080 never opened in the firewall, and a backup of TWIST_DATA.
